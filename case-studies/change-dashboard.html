Demo company

Leadership can't see where changes stand

One page for every change request

The situation

At Lumen Photonics, every change request was recorded in a list, but nobody could see the big picture: what was stuck, which approvals were slow, or whether the rules had held before month-end close.

What changed

A dashboard turns that history into one page for three audiences. The weekly change review starts with open requests by age, oldest first. Each process owner can select their own name to see exactly what's waiting on them. Finance and audit check two numbers that should always be zero: changes that skipped financial review, and changes released during month-end close.

In the demo data, it showed one approver taking about 3.5 days to decide, against 1.6 to 2.5 days for everyone else. That's the case for adding an escalation step.

Before

  1. Requests in a long list
  2. Ask around about status
  3. Problems found at audit

After

  1. Oldest requests first
  2. Each approver sees their queue
  3. Control checks before close

What it meant for the team

  • Bottlenecks are visible, with numbers behind them.
  • Approvers see their own queue without asking.
  • Finance and audit can check the controls before every close.

Built with: Power BI, SharePoint
